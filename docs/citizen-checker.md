# 民眾版「收到處分怎麼辦」自助檢查工具 — 設計理念

> 這份文件說明民眾版的設計取捨，之後可改寫成技術文章。
> 程式進入點：`app/citizen_app.py`；核心邏輯：`core/citizen.py`、`core/citizen_template.py`。

## 一、問題：民眾收到處分書後最容易踩的三個雷

一般民眾收到行政處分（罰單、裁罰、限期改善通知等）後，常見三個困擾：

1. **不知道還剩幾天可以救濟**。訴願期間 30 日看似簡單，但起算日（送達生效日）、
   寄存送達要加 10 日、末日遇假日要順延，稍微算錯就可能錯過期限。
2. **不知道處分書本身有沒有問題**。例如沒寫法令依據、可能已過裁處期限。
3. **不知道下一步怎麼做**。訴願書要寫什麼、寄去哪裡、郵戳算不算數。

這個工具把承辦人版已經有的規則模組（`core/timeline.py`、`core/defects.py`）
直接拿來服務民眾，讓同一套可信賴的計算邏輯普及給一般人。

## 二、為什麼期限計算「不用 LLM」

**期限攸關人民權益，只能用確定性規則，不能交給會幻覺的模型。**

這是整個設計最重要的一條原則，理由有三：

- **可驗證**：規則的輸出對同樣的輸入永遠一致，可以寫單元測試逐案釘住
  （見 `tests/test_timeline.py`、`tests/test_holidays.py`）。模型的輸出會漂移，
  無法對「115/10/02 送達，期限是哪天」這種問題給出可保證的答案。
- **可追溯**：每個期限都附上計算過程說明（`deadline_explanation`），
  例如「送達生效日 … → 自次日起算 30 日原末日為 … → 因 … 順延至 …」，
  民眾與承辦人都能逐步核對。模型即使答對也說不清「為什麼」。
- **零成本、零外部相依**：純 Python 計算不呼叫 Bedrock，也就不佔用競賽
  ≤ 1 RPS 的配額、不需要 `boto3`、不連 AWS，部署與離線測試都單純。

與此一致，處分書瑕疵檢查也只採用 `core/defects.py` 的**純規則項 D1–D6**，
不使用需要 LLM 的 D7–D13。能用規則判定的客觀錯誤，就不交給模型。

### 國定假日與補班日

期限末日若落在假日要順延，但「假日」不只是週末。本工具內建
行政院人事行政總處的「政府行政機關辦公日曆表」（`data/calendar/`，
來源與下載日期見該資料夾 README），因此能正確處理：

- **國定假日 / 彈性放假**落在平日 → 順延
- **補班日**（補行上班的週六）→ **不**順延
- 日曆未涵蓋的年份 → 退回只判斷週末，並明確標示「日曆不完整」提醒使用者

## 三、保守提醒原則

拿不準的情況，一律往「對民眾最安全」的方向提醒，**絕不顯示任何保證**：

- **送達方式「不確定」**：以最早可能的生效日（當天收受）計算，給出最短的期限，
  並提醒實際若為寄存送達會往後順延。寧可讓人提早準備，不讓人誤以為還很久。
- **沒有救濟教示**：依行政程序法§98 III，期間可能延長為一年；但認定存在風險，
  因此**同時顯示一年與 30 天兩個期限，並強烈建議以 30 天為準**。
- **措辭**：瑕疵一律用「可能」「建議確認」，不說「你一定可以主張」「你會贏」。
- **逾期**：顯示「可能已逾期」，並說明是否真的逾期以受理機關認定為準，引導諮詢專業，
  而不是直接宣告沒救。
- **郵戳 vs 收到日**：明確提醒訴願書以「受理機關實際收到日」為準，非郵戳日
  （訴願法§14 III），建議掛號並提早寄出。

介面頂端與底部都固定顯示免責聲明，強調本工具**不構成法律意見**。

## 四、資料不落地

- 第一階段**不儲存任何使用者輸入**：沒有資料庫、不寫檔、不記錄個資到 log。
- 介面只用 Streamlit 的 `st.session_state` 在瀏覽器工作階段暫存，關掉即消失。
- 訴願書 `.docx` 直接在記憶體 buffer 產生後供下載，不在伺服器落地。
- 這同時呼應競賽規範「禁止把個人資料匯入 AWS 帳戶」：民眾版根本不送任何資料到 AWS。

## 五、架構：一套核心、民眾版只是另一層外殼

民眾版沒有重寫任何業務邏輯，而是沿用專案「一套核心、多種外殼」的設計：

```
core/timeline.py   期限與日期規則（+ holidays.py 假日順延）
core/defects.py    D1–D6 純規則瑕疵檢查（已拆除對 boto3 的硬相依）
      │
      ├─ core/citizen.py           把民眾表單 → 檢查結果（純函式 dict→dict）
      ├─ core/citizen_template.py  檢查結果 + 填寫資料 → 訴願書範本（Markdown / .docx）
      │
      └─ app/citizen_app.py        手機優先的 Streamlit 外殼（取輸入→呼叫 core→顯示）
```

外殼只負責「取輸入 → 呼叫 core → 顯示／下載」，業務邏輯全在 `core/` 的純函式。
為了讓民眾版能在**沒有 `boto3`** 的乾淨環境部署，`core/defects.py` 的
`bedrock_client` 匯入已改為延遲載入（只有承辦人版用到 LLM 的 `health_check()`
在需要時才載入），`core/citizen.py` 則完全只依賴純規則模組。

## 六、測試與驗證

- `tests/test_timeline.py`：日期解析、寄存 +10、期限順延、裁處權時效（含 2/29 閏日邊界）
- `tests/test_holidays.py`：國定假日順延、補班日不順延、日曆不完整退回週末
- `tests/test_citizen.py`：各 urgency、逾期、送達方式不確定、無救濟教示、欄位全空
- `tests/test_citizen_template.py`：範本段落齊全、缺欄位有佔位符、不編造內容、.docx 輸出
- `tests/test_defects_no_boto3.py`：攔截 `boto3` import，證明 D1–D6 不依賴 AWS SDK

CI（`.github/workflows/ci.yml`）另有 `citizen-no-boto3` 工作：**只安裝
`requirements-citizen.txt`**（不含 boto3），斷言 boto3 不存在後跑民眾版測試，
作為「民眾版可獨立於 AWS 部署」的自動化證明。

## 七、第二階段（規劃）

- 上傳處分書照片或 PDF 自動帶入欄位（會用到 LLM，需評估費用；自動帶入一律讓使用者確認後才計算）
- 以 Bedrock KB 檢索相似歷史訴願決定供民眾參考
- 匿名使用統計（只記「有人用了」與 urgency 類別，不記任何欄位內容）
